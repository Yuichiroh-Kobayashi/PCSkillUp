# ドット絵データクエスト

― PC操作と情報のデジタル化をつなぐミッション教材 ―

## 概要

ドット絵データクエストは、中学校技術科でPC操作の基本技能と情報のデジタル化をつなげるためのWeb教材です。

クリックやドラッグでドット絵を作りながら、コピー＆ペースト、スクリーンショット、貼り付け提出の流れを練習します。あわせて、ドット絵・画素・色数などを通して、情報をデジタル化して扱う考え方へ接続します。

扱う技能は次の通りです。

- クリック
- ドラッグ
- Ctrl + C での文字列コピー
- Ctrl + V でのペースト
- Win + Shift + S でのスクリーンショット
- スクリーンショットを任意アプリへ貼り付け提出
- ドット絵・画素・色数など、情報のデジタル化への接続

## ステージ構成

### ステージ1：ビットゲート

- 16×16x2色
- 見本の「1」があるマスを黒く塗る
- 文章のコピー＆ペースト練習
- クリア後は「再チャレンジ」または「ステージ2へ」

### ステージ2：ピクセルキャプチャー

- 32×32x4色（白色・銀色・灰色・黒色）
- 見本との完全一致は要求しない
- Win + Shift + S によるスクリーンショット練習
- 任意のアプリに Ctrl + V でペースト

## 画面テーマ（ライト / ダーク）

- ライトモードとダークモードに対応しています。
- 起動時は、端末またはブラウザの設定（system preference）に従います。
- 画面右上の切替ボタンで、手動でライト / ダークを切り替えられます。
- ボタンの文言は「次にできる操作」を示します。
  - ライト表示中：`暗いモードにする`
  - ダーク表示中：`明るいモードにする`
- 手動で選んだテーマは保存しません（localStorage / sessionStorage / Cookie / IndexedDB のいずれも使いません）。
- そのため、リロードや再起動の後は、ふたたび端末・ブラウザの設定から始まります。
- 手動切替をしていない間は、OS・ブラウザ側の設定変更に画面が追従します。手動切替の後は、そのページを閉じるまで手動の選択を優先します。
- テーマ変更は見た目だけの変更です。ステージ、見本、作業グリッドの内容、選択中の色、ペースト欄の入力、クリア状態は保持されます。

## 配色とアクセシビリティの方針

- CUD / アクセシビリティに配慮した配色（CUD-informed color design）で設計しています。
- 色そのものではなく、意味（semantic role）に名前を付けたカラートークンで構成し、ライトとダークで同じ役割名を共有しています。
- 状態表示は色だけに依存しません。成功・未完了・次の操作は、記号（✓ / ! / →）、文言、枠線の形と位置、色の4点で示します。
- CLEAR表示は、色を除いても「CLEAR!」「ミッション完了」「達成項目」「再チャレンジ」「ステージ2へ」だけで内容が分かるようにしています。
- コントラストは、通常のテキストで4.5:1以上、重要なUIの境界・フォーカス表示で3:1以上を設計targetとして確認しています。
- ライト・ダークの両方をグレースケールでも確認し、ステージ・成功・未完了・CLEAR・主/副ボタン・キー操作・フォーカスが判別できることを確かめています。
- エフェクトの色はテーマのトークンを参照します。エフェクトは装飾的な手がかりであり、重要な状態を色だけで示すことはありません。
- `prefers-reduced-motion: reduce` では、移動や拡大の動きを減らし、枠線・文字・色による強調は残します。情報量は減らしません。

なお、本教材はCUD認証やWCAGへの全面適合を主張するものではありません。上記は設計上の方針と、確認したtargetの記載です。

### ドット絵の色はテーマで変わりません

白色・銀色・灰色・黒色の4色は、UIのテーマ色ではなく教材データです。ライト / ダークのどちらでも反転・再配色しません。BMP出力のパレットやビット深度もテーマの影響を受けません。

## ローカル確認方法

Python が使える環境で以下を実行します。

```powershell
py -m http.server 8000 -d docs
```

ブラウザで開くURL:

```text
http://localhost:8000/
```

構文チェック:

```powershell
node --check docs/app.js
node --check docs/patterns.js
node --check docs/bmp.js
```

配色トークンのコントラスト確認（開発時のみ。アプリ本体には依存関係を追加していません）:

```powershell
node tools/check-contrast.mjs
```

## 授業での見取り観点

- 見本を見て、クリック/ドラッグでぬり分けできるか。
- 文をドラッグ選択して Ctrl + C でコピーできるか。
- ペースト欄へ Ctrl + V でペーストできるか。
- 4色ドット絵で、パレットを選んでからぬれるか。
- Win + Shift + S で提出したい範囲を囲む流れを理解できるか。
- 先生が指示するアプリに Ctrl + V で貼り付ける流れを理解できるか。
- 色数やマス数の違いとデータ量の関係に気づけるか。
- 画面が見えにくいとき、テーマ切替ボタンで明るさを変えられるか。

## 運用上の留意点

- このアプリ自体は、個人情報の入力・保存・送信を行いません。
- ただし、通常のWebアクセスとしてGitHub側のアクセスログは発生します。
- HTML/CSS/JavaScript の静的ファイルのみで動作します。
- Webアプリ側で Win + Shift + S を検出しません。
- Webアプリ側でスクリーンショットの貼り付け完了を検出しません。
- 外部API、解析タグ、トラッカー、CDN、外部画像、外部フォントは使用していません。
- テーマの選択を含め、ブラウザへの保存（localStorage / sessionStorage / Cookie / IndexedDB）は行いません。
